Diferencias con SQLClass6 (driver)

SQLMariaClass respeta el comportamiento de la SQLClass6. Estas son las diferencias, todas a favor salvo que se indique.

TemaSQLClass6 con driverSQLMariaClass
Tabla de trabajoNecesita la tabla sqlclass (N campos de M caracteres)No usa archivo; Init recibe el archivo solo por compatibilidad
Columnas y largoLimitados por el registro (por ejemplo 25 campos de 49)Sin límite
Col(n)Campo n del registroValor que mandó el servidor; '' si es NULL
Columns() / Field(n)Lo que dedujo el parser del SELECTCantidad y nombres reales que manda el servidor
Records()Hace un SELECT COUNT(*) aparteCuenta el resultado ya leído (exacto con GROUP BY / DISTINCT)
Procedimientos almacenadosExecSP convierte EXEC en CALLIgual, y descarta el resultado extra del CALL
Sentencias aceptadas por ParseSELECT, INSERT, UPDATE, DELETE, CREATE...Además SHOW, DESCRIBE, EXPLAIN, REPLACE, USE, WITH, LOCK..., y SELECT sin FROM
Conexión caídaErrorReconecta y reintenta una vez (errores 2006 / 2013)
LoadQueue con ventanaPorcentaje invertidoPorcentaje correcto
Nuevos-InitMaria, ColByName, IsNull, Escape, Quote, InsertId, AffectedRows, ErrorText, ErrorCode, ServerVersion, BeginTransaction, Commit, Rollback, KeepCase, Db

Lo que se mantiene igual (a propósito)

  • Exec pasa la consulta a minúsculas (salvo KeepCase).
  • Códigos de retorno: 0 = bien, 1 = error; Next() devuelve 0 cuando trajo una fila.
  • SilentMode, Debug / Debug_Limit (aviso de consulta lenta), MaxReads, FreeQueue, LogFile, ShowProgress.
  • Embeds de métodos y métodos virtuales (TakeRecord, TakeSelect...).
Los métodos de la SQLClass6 no son VIRTUAL (salvo Init y los Take*). Por eso el objeto tiene que ser de tipo SQLMariaClass: una referencia &SQLMsClass que apunte a un SQLMariaClass llamaría al código del driver.
