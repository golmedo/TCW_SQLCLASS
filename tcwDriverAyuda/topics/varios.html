Un procedimiento puede devolver varios SELECT, y una consulta puede tener varias sentencias. Se lee el primer resultado como siempre y NextResult() pasa al siguiente (devuelve Level:Notify cuando no hay más).

  SQL.AddParam(Cliente)
  SQL.ExecSP('EXEC dbo.Resumen ?')        ! MariaDB: ExecSP('CALL Resumen(?)')
  LOOP UNTIL SQL.Next()                   ! resultado 1
  END
  IF SQL.NextResult() = Level:Benign      ! resultado 2
    LOOP UNTIL SQL.Next()
    END
  END
  • Los conteos intermedios de un procedimiento (UPDATE antes del SELECT) se saltean solos.
  • Una consulta UPDATE ...; SELECT ... queda directamente en el resultado del SELECT.
  • MariaDB: la conexión habilita CLIENT_MULTI_STATEMENTS; ExecSP('EXEC sp p1, p2') se manda como CALL sp(p1, p2) y el resultado de estado del CALL se descarta.
  • SQL Server: ExecSP('CALL sp(p)') va con el escape de ODBC {CALL sp(p)}.

Nota: un resultado con resultados pendientes sin leer no traba la consulta siguiente: la clase los descarta antes de ejecutar.
